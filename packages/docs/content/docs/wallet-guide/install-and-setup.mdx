## Install from the official store

Use the [official Chrome Web Store listing](https://chromewebstore.google.com/detail/noir-wallet/mfoghjbpfanobmnoemoepenjjcmfpmdn). After installation, pin the extension from Chrome's extensions menu.

## Create or restore

<Tabs items={['New wallet', 'Restore wallet']}>
  <Tab value="New wallet">
    Choose **Create Wallet**, set a local password, and record the recovery phrase offline. Complete
    the phrase confirmation before funding the wallet.
  </Tab>
  <Tab value="Restore wallet">
    Choose **Import wallet** and enter the existing recovery phrase in order. Select the wallet's
    first-use date (or an earlier date if unsure) or its birthday block height in **Sync
    Optimization**, then set a password for this browser installation.
  </Tab>
</Tabs>

## Wallets and accounts

Noir Wallet can hold multiple wallets and accounts. A connected dApp may request read access to more than one account, but the wallet keeps a primary account for actions that operate on a single account.

## Synchronization

Zcash wallet history is discovered by scanning the chain. After an import or a long period offline, balances and activity can take time to catch up.

- The interface can show locally cached information while synchronization continues.
- Actions remain unavailable until their prerequisites are ready.
- Keep the browser open if the wallet indicates that an initial scan is still running.
- If sync pauses, check the network connection and restart the extension if it remains paused.

On Mainnet, open **Settings > RPC Endpoint** to choose a provider or enable **Auto**. Auto switches among managed providers when needed. If a fixed provider is temporarily unavailable, retry later or select another provider. If it is removed from the available providers, the wallet switches to Auto. Testnet uses its fixed synchronization endpoint.

## Transaction broadcasting

ZeroIndexer broadcasting is enabled by default under **Settings > Security & Privacy**. Open **Nodes** in the **ZeroIndexer** card to use **Auto**, choose an official node, or add and select a custom node. Auto orders official nodes by reachability and probe latency; custom nodes are used only when explicitly selected. Adding a custom node saves it without changing the selection. Deleting a selected custom node restores Auto. Choices are saved separately for Mainnet and Testnet and retained when ZeroIndexer is turned off. The preferred-node indicator and latency describe probe results, not the node that accepted a transaction.

Transactions containing Orchard try the selected ZeroIndexer node, or the ordered official nodes in Auto. If every attempt fails, the wallet broadcasts the same transaction through its ordinary RPC, including when a node was manually selected. During synchronization, status lookups for locally created Orchard transactions also try these nodes before falling back to the ordinary RPC. Other transactions use the ordinary RPC directly. Turning off ZeroIndexer uses the ordinary RPC for all broadcasts and these status lookups. These settings do not change the synchronization provider or compact-block CDN.
